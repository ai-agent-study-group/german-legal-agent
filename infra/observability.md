# 관측·장애 대응 검토

상태: **공개 서비스 운영 전 검토 필요**. 아래는 적용할 요구사항과 확인 절차이며 관측 도구·알림이 이미 구성되었다는 뜻이 아닙니다. 서비스 소유자, 도구, 보관 위치·기간, 접근 권한과 알림 임계값은 팀이 확인한 뒤 정합니다.

## 현재 확인된 범위

- `web/`은 데모 제공자를 사용하며 `/api/chat`에서 오류 시 일반적인 503 메시지를 반환합니다. 전용 health 엔드포인트와 운영 대시보드는 이 저장소의 웹 구현에서 확인되지 않았습니다.
- 별도 backend의 `/health`는 프로세스가 요청에 응답하는지만 나타냅니다. 모델이나 외부 데이터 소스의 정상 상태를 보장하지 않습니다.
- `agent/legal_agent/graph.py`의 `ask()`는 기본 `verbose=True`에서 도구 인자와 결과 일부를 출력합니다. 질문에서 유래한 내용이 인자에 포함될 수 있으므로 운영 로그에 안전하다고 가정하면 안 됩니다. `agent/run_cli.py`는 답변을 터미널에 출력합니다.
- 수집기의 `--debug`는 외부 응답 본문 일부를 출력합니다. 실패 기록과 원문 파일에도 내용을 포함할 수 있으므로 공유·업로드 전에 검토합니다.
- Next.js 설정에 `browserToTerminal`이 활성화되어 있습니다. 개발 환경의 브라우저 로그가 터미널에 전달될 수 있으므로 실제 민감 정보를 실습에 사용하지 않습니다.

## 도입 전 결정할 최소 지표

요청 수·오류율과 지연 시간(p95), 모델 호출 수·토큰·비용, 수집 성공·실패 건수를 후보로 합니다. 요청 ID로 단계별 오류를 연결하되 ID에 사용자 식별 정보나 질문을 넣지 않습니다. 각 지표의 측정 지점, 집계 주기, 알림 기준, 수신 채널과 담당자를 결정하고 테스트합니다. 대시보드 URL은 실제 생성 후 접근 권한을 확인해 기록합니다.

## 로그와 개인정보 요구사항

- 기본적으로 질문·답변·도구 인자와 결과·판례 원문·인증 헤더·키를 로그와 trace에서 제외합니다. 허용 필드만 명시하는 방식으로 설계하고 예외는 담당자 승인 후 검토합니다.
- 오류는 원문 대신 분류 코드와 요청 ID를 사용합니다. 외부 SDK·플랫폼의 자동 수집, 예외 메시지와 HTTP body 기록도 별도 확인합니다. 단순 문자열 치환만으로 모든 민감 정보가 제거되었다고 간주하지 않습니다.
- 실제 운영 경로에 기존 agent의 verbose 출력이 연결되지 않도록 확인하고, 필요한 수정과 회귀 테스트를 별도 구현합니다. 수집 debug와 CLI 출력도 운영 로그 수집 범위에 포함되는지 확인합니다.
- 로그의 보관 기간, 데이터 위치, 접근 권한, 삭제 절차, 도구 비용·무료 한도와 개인정보 처리 책임을 확정한 후 운영 설정을 적용합니다.

## 장애 대응 초안

| 상황 | 최초 확인 | 대응 및 복구 확인 |
| --- | --- | --- |
| 웹 응답 실패 | 배포 상태, 프로세스 로그와 최근 변경 확인 | 담당자에게 알리고 원인을 분류. 필요 시 승인된 이전 배포로 복원하고 페이지와 데모 API를 재확인 |
| 모델 timeout·한도 오류 | 제공자 상태와 비밀값 노출 없는 오류 분류 확인 | 재시도·비용 한도 정책에 따라 대응하고 정상 응답과 지표 회복 확인. 질문 본문은 기록하지 않음 |
| 수집 실패 | 종료 코드, 실패 건수와 외부 서비스 상태 확인 | 실패 원인을 확인하고 기존 데이터 보존 여부를 점검한 뒤 승인된 절차로 재실행. 중복 유료 호출에 유의 |

연락 채널, 당직·담당자, 알림 임계값, Railway의 실제 로그 조회 경로와 롤백 단계는 서비스 설정 확인 후 기입합니다. 로그가 유출된 경우 키 폐기·교체 및 접근 범위 점검을 우선합니다.

## 검증과 완료 조건

운영 구성이 정해지면 가짜 질문과 가짜 비밀값으로 정상 요청, 모델 timeout, 수집 실패를 재현합니다. 응답·로그·trace·오류 메시지·대시보드에 가짜 민감값이 없는지 확인하고, 요청 ID와 오류 분류·알림·복구를 점검합니다. 실제 키나 법률 상담 사례를 테스트 데이터로 사용하지 않습니다. 확인한 환경, 날짜, 도구 버전과 결과를 기록합니다.

도구·예산·보관 정책과 실제 배포 경로를 확인하기 전에는 임계값이나 보안 효과를 추정해 운영 설정을 적용하거나 #24를 완료 처리하지 않습니다. 실패 시나리오와 로그 마스킹의 실제 검증은 아직 수행되지 않았습니다.
