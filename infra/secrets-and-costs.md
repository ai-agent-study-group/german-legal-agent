# 환경변수·비밀값·비용 운영 기준

이 문서는 현재 구현과 실제 모델 운영 전 합의할 항목을 구분합니다. 데모 웹과 별도 agent·backend·수집 스크립트는 서로 다른 실행 단위이며 환경변수가 자동 공유되지 않습니다. 실제 키는 예시 파일이나 Git에 기록하지 않습니다.

## 현재 설정

| 실행 단위 | 이름 | 필수 여부와 의미 |
| --- | --- | --- |
| `web/` | `AGENT_PROVIDER` | 선택. 생략 또는 `demo`만 지원하며 키 없이 동작. 다른 값은 설정 오류 |
| `agent/` | `GROQ_API_KEY` | 실제 Groq 호출에 필요. `run_cli.py`는 dotenv로 로컬 `.env`를 읽음. 모델은 현재 코드에 지정됨 |
| `backend/` | `APP_ENV` | 선택. 기본 `local`; `local`, `dev`, `prod` 허용 |
| `backend/` | `API_TOKEN` | `prod`에서 필수인 서버 인증 비밀값. 로컬 테스트에는 테스트 전용 값을 사용 |
| `ingestion/Openlegaldata/` | `OLDP_API_TOKEN` | 선택. Open Legal Data 인증 수집용 토큰 |
| `ingestion/Openlegaldata/` | `OPENAI_API_KEY`, `OLDP_SUMMARY_MODEL` | 판례 AI 요약 시 둘 다 필요. 법률만 수집할 때는 불필요 |

웹은 `web/.env.example`, agent와 backend는 각 폴더의 `.env.example`을 참고합니다. 예시는 설정 이름만 담으며 실제 자격 증명이 아닙니다. 수집 스크립트는 실행 셸의 환경변수를 사용합니다. 현재 웹 CI는 외부 키 없이 동작합니다. 현재 CI가 별도 agent 또는 backend를 검증한다는 뜻은 아닙니다.

## 설정과 접근

- 로컬: 각 실행 단위의 `.env` 또는 실행 셸에 설정하고 공유하지 않습니다. `.env.example`에는 실제 값 대신 빈 값이나 명백한 예시만 둡니다.
- GitHub Actions: 필요한 경우 저장소 또는 환경의 Secrets에 등록하고 필요한 job에만 전달합니다. 현재 웹 CI에는 실제 서비스 키가 필요하지 않습니다. fork PR 등에는 비밀값이 제공되지 않을 수 있으므로 키 없는 테스트를 유지합니다.
- Railway: 필요한 서비스의 Variables에만 등록합니다. 빌드 로그, 이미지, 클라이언트 번들에 서버 비밀값을 넣지 않습니다. `NEXT_PUBLIC_` 접두사는 브라우저에 공개되므로 비밀값에 사용하지 않습니다. 환경별 키를 분리합니다.
- DevOps 담당자는 접근 가능한 인원과 등록 위치를 관리하고, 제공자 계정 소유자 및 백업 담당자는 팀에서 확정합니다. 비밀값 자체를 이슈·PR·채팅에 남기지 않습니다.

## 유출 대응

1. 제공자에서 노출된 키를 즉시 폐기하거나 회전하고 사용량·접근 기록을 확인합니다.
2. GitHub/Railway 등 해당 위치에 새 값을 등록하고 서비스 재배포 또는 재시작 후 동작을 확인합니다. 이전 값은 제거합니다.
3. 노출 경로와 영향 범위를 기록하고 팀에 공유합니다. Git 이력에서 삭제해도 키는 안전해지지 않으므로 폐기를 먼저 합니다. 이력 정리는 저장소 관리자와 협의합니다.
4. 로그·오류 응답·데이터 산출물에 추가 노출이 없는지 확인하고 재발 방지 조치를 기록합니다. 로그에는 대화 본문이나 비밀값을 출력하지 않습니다.

## 비용과 제한: 실제 모델 연동 전 필수 결정

- 제공자·모델, 환경별 예산과 책임자, 알림 임계값 및 한도 도달 시 차단 방식을 정합니다. 제공자의 알림이나 예산 설정만으로 하드 차단이 보장되는지 확인합니다.
- 사용자별 요청 빈도·동시 요청·입력 크기·출력 토큰·타임아웃·재시도 한도를 정하고 서버 측에서 강제합니다. 현재 웹의 입력 검증은 비용 한도가 아닙니다.
- 테스트는 가짜 제공자와 테스트 키를 사용하고 CI에서 유료 호출을 하지 않습니다. 수집 작업은 신규 수집 상한과 재시도 시 중복 호출 가능성을 고려해 실행 전에 예산을 확인합니다.
- 사용량·오류·지연을 민감한 질문이나 원문 없이 관측합니다. 세부 관측 및 개인정보 방침은 #24에서 정합니다.

## 점검과 미결 사항

루트 `.gitignore`는 `.env`와 `.env.*`를 제외하고 `.env.example`을 허용합니다. 이미 추적 중인 파일은 ignore 규칙을 추가해도 추적이 중단되지 않습니다. `web/data/raw/`와 일부 `web/data/pending/` JSON은 이미 추적 중이므로, 새 수집 결과를 커밋하기 전 내용·출처·개인정보 및 이용 조건을 검토합니다. 로그와 실패 결과에도 외부 오류 내용이 들어갈 수 있습니다.

저장소 관리자는 GitHub의 secret scanning 및 push protection 활성화 가능 여부와 실제 설정을 확인하고, 지원되지 않는 경우 대안을 정합니다. 이 문서는 해당 기능의 활성화를 의미하지 않습니다. 실제 서비스 키가 추가될 때 설정 위치·키 회전과 로그 마스킹 테스트를 해당 구현 PR에 포함합니다.
