# Germany Life Agent — 기존 데모 실행 안내

이 문서는 현재 `web/`에 모여 있는 데모의 구현·실행 방법을 설명합니다.
아래 Next.js·TypeScript·Python·파일 경로는 현재 데모의 선택이며, 프로젝트의 기술 스택이나 최종 폴더 구조는 미정입니다.
분리 여부와 경로는 [구조 논의 문서](../docs/STRUCTURE.md)를 참고하세요.

독일 거주 한국인을 위한 주거·임대 / 체류·비자 정보 안내 서비스의 기반입니다.
이호수가 준비한 웹 기반으로, 현재는 킥오프·기획 단계입니다. 참가자는 자료 검색·읽기와 에이전트 동작을 함께 배웁니다.

[참여자 소개·역할 논의](../docs/TEAM.md) · [프로젝트 논의 항목](../docs/PROJECT_PLAN.md) · [10월 15일 킥오프](../docs/meetings/2026-10-15.md)

첫 MVP의 분야·기능·역할·일정은 미정이며 2026-10-15 킥오프에서 논의할 예정입니다.
아래 두 분야의 화면·TODO는 현재 상태와 확장 후보를 설명하며, 합의된 개발 계획은 아닙니다.

**현재는 실제 AI 모델이 없는 규칙 기반 데모입니다.** API 키나 인터넷 자료 수집 없이 실행할 수 있습니다.
실제 모델을 연결하면 모델이 검색 도구와 다음 행동을 선택하도록 발전시킵니다.

## 실행

Node.js 20.9 이상, npm을 사용합니다. 프로젝트 폴더에서:

```bash
npm install
npm run dev
```

터미널에 표시된 주소(기본 http://localhost:3000)를 엽니다.
다른 앱이 3000번 포트를 사용하면 `npm run dev -- --port 3001`로 실행합니다.

- `/`: 소개와 분야 선택
- `/housing`: 주거·임대 데모
- `/visa`: 체류·비자 데모
- `/admin`: 스터디원용 페이지별 구현·학습 안내. 주소로 직접 접근하며 공개 메뉴에는 표시하지 않습니다.
- `/study`: 기존 주소를 `/admin`으로 이동합니다.

`.env.example`은 설정 이름의 예시입니다. 현재 데모에서는 `.env.local`을 만들 필요가 없습니다.
실제 키는 추후 선택한 제공자의 서버 전용 어댑터에 연결하고 Git에 올리지 않습니다.

## 화면 뒤에서 일어나는 일

```text
자료 준비: 공식 웹 → Python 수집 → 검토 대기 파일 → 사람이 승인 → 앱 자료
질문 응답: 채팅 → 서버 → 검색 도구 → 읽기 도구 → 답변과 출처
```

현재 데모는 검색→첫 결과 읽기→준비된 설명 표시 순서로 움직입니다.
비자 페이지에서 목적 없는 연장 질문을 하면 유학/취업을 묻습니다.
도구 기록은 실제 실행 결과이며, AI의 생각이나 실시간 진행 상황을 가장한 기록이 아닙니다.

예제는 공식 페이지 네 건을 2026-10-11에 원문과 대조해 작성한 짧은 한국어 요약입니다.
법률 전문가의 검수나 정확도 인증이 아닙니다. 모든 상황을 다루지 않으며 일반 정보 안내입니다.
주거 자료는 BGB §551·§568, 체류 자료는 Make it in Germany의 유학·전문인력 취업 안내입니다.
[자료 관리](docs/DATA.md)에서 원문 링크와 갱신 방법을 확인하세요.

## Python 자료 수집

Python 3.10 이상을 권장합니다. Node.js 앱과 별도로 실행합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r scripts/scrape/requirements.txt
python3 scripts/scrape/collect.py
```

Windows PowerShell에서는 활성화 명령 대신 `.venv\Scripts\Activate.ps1`을 사용합니다.
수집할 URL과 본문 위치는 `scripts/scrape/sources.json`에서 지정합니다.
스크립트는 `data/pending/<자료ID>.json`에만 저장합니다. 실패 시 기존 파일을 유지하고 종료 코드 1을 반환합니다.
자동 링크 탐색이나 정기 수집은 없습니다. 사이트가 바뀌면 본문 위치(selector)를 고쳐야 합니다.

**승인하기 전에 반드시** 원문과 본문을 비교하고, 메뉴·광고·중복 내용·개인정보를 제거합니다.
한국어 검색어를 확인하고, 데모 답변으로 사용할 경우 본문을 짧은 한국어 요약으로 편집해 `language`도 수정합니다.
그다음 검토한 자료 한 건만 승인합니다.

```bash
python3 scripts/scrape/review.py --approve housing-deposit
```

승인은 같은 ID의 앱 자료를 교체하므로 파일 변경 내용을 확인하세요.
앱은 `reviewed: true`인 자료만 읽습니다. 수집을 하지 않아도 동봉된 예제로 동작합니다.

## 공식 페이지 수집 예시

스크롤링(화면을 아래로 이동)과 스크래핑(페이지 내용을 가져오기)은 다릅니다.
현재 예제는 조문이 HTML에 포함되어 있어 스크롤 없이 본문을 추출합니다.
아래 링크를 열어 제목 아래 번호가 붙은 문단을 확인하세요. `.jurAbsatz`는 Python이 해당 문단을 고르는 이름(selector)입니다.

| 분야 | 실제 수집 페이지                                                                                  | 가져올 부분                           | 검토 대기 파일                        |
| ---- | ------------------------------------------------------------------------------------------------- | ------------------------------------- | ------------------------------------- |
| 주거 | [BGB §551 — 보증금](https://www.gesetze-im-internet.de/bgb/__551.html)                            | (1)~(4)항 조문 본문                   | data/pending/housing-deposit.json     |
| 주거 | [BGB §568 — 종료 통지](https://www.gesetze-im-internet.de/bgb/__568.html)                         | (1)~(2)항 조문 본문                   | data/pending/housing-termination.json |
| 체류 | [AufenthG §16b — 유학](https://www.gesetze-im-internet.de/aufenthg_2004/__16b.html)               | 각 항의 본문; 첫 검토는 (1)·(2)항부터 | data/pending/visa-study-law.json      |
| 체류 | [AufenthG §18b — 학위 소지 전문인력](https://www.gesetze-im-internet.de/aufenthg_2004/__18b.html) | 제목 아래 조문 본문                   | data/pending/visa-work-law.json       |

§18b 한 조문은 취업 요건 전체를 설명하지 않습니다. 관련 규정과 공식 안내를 함께 검토해야 합니다.

### 한 페이지로 실습하기

프로젝트 폴더에서 Python 환경을 준비한 뒤 실행합니다.

```bash
# 보증금 페이지 한 건만 검토 대기 파일로 수집
python3 scripts/scrape/collect.py --manifest scripts/scrape/deposit-example.json

# 원문과 data/pending/housing-deposit.json을 직접 비교한 뒤에만 실행
python3 scripts/scrape/review.py --approve housing-deposit
```

수집만 하면 앱 자료는 바뀌지 않습니다. 승인하면 같은 ID의 기존 앱 자료가 교체됩니다.
전체 네 건은 `python3 scripts/scrape/collect.py`로 수집합니다.
현재 `.jurAbsatz` 본문을 선택하고 메뉴·스타일·스크립트는 제외합니다. 페이지 제목과 키워드는 수집 목록에서 지정합니다.

[저장 파일 예시와 상세 검토 방법](docs/DATA.md#저장되는-json-구조) · 웹에서는 `/admin#collection-examples`에서 확인할 수 있습니다.

## 실습 안내

비개발자: 예시 질문 실행 → 활동 기록 확인 → 원문 비교 → 필요한 질문/검색어 작성.
개발 경험자: 각 주차의 함수 수정 → 같은 질문 다시 실행 → 결과 비교.
둘이 짝을 이루어 실행과 설정 변경을 함께 합니다.

1. **AI 연결:** `lib/providers/types.ts`를 보고 선택한 모델의 어댑터를 작성합니다.
2. **자료 검색:** `lib/tools/sources.ts`에서 한국어 키워드와 검색 결과를 개선합니다.
3. **에이전트:** `lib/agents/run.ts`에서 모델의 요청→실행→결과 전달을 관찰합니다.
4. **평가:** `docs/EVALUATION.md`의 질문으로 두 팀이 서로 테스트합니다.

[4주 실습 안내](docs/STUDY.md) · [설계](docs/ARCHITECTURE.md) · [디자인](docs/DESIGN.md)

## 실제 AI를 연결할 위치

`ModelProvider.decide()`는 현재 질문, 담당 규칙, 도구 정의, 이전 도구 실행 결과를 받고
`answer` 또는 `tool_call`을 반환합니다. `lib/providers/demo.ts`가 현재 구현입니다.
실제 제공자의 어댑터는 검색 결과를 각 API의 도구 결과 메시지로 변환해야 합니다.
`callId`로 모델 요청과 결과를 연결하고 모델 호출에 시간 제한을 설정합니다.

모델을 결정한 뒤 아래를 함께 변경합니다.

- 새 어댑터 구현과 `lib/providers/index.ts`의 선택 기능.
- provider 및 API 응답의 `mode`에 `live` 추가.
- 웹의 데모 표기와 실제 실행 기록 설명.
- 요청 제한·모델 사용 비용 관리·오류/시간 초과 테스트.

현재 `AGENT_PROVIDER=demo`만 지원합니다. 다른 값을 넣으면 요청에 설정 오류가 반환됩니다.
역할 규칙을 고치는 실습은 데모 답변에 영향을 주지 않습니다. 데모는 프롬프트를 이해하는 모델이 아니기 때문입니다.
데모 동작을 고치려면 `demo.ts`를 수정하고, 프롬프트 효과를 보려면 실제 모델을 연결하세요.

## 검증

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run test:scrape
```

Python 검증은 위 Python 의존성을 설치한 환경에서 실행합니다.
`npm start`는 빌드 후 프로덕션 모드로 실행합니다. 개발 서버가 실행 중일 때 같은 `.next`에 빌드하지 마세요.

대화는 브라우저 메모리에만 유지되며 새로고침·페이지 이동·초기화 시 사라집니다.
사용자가 초기화하면 진행 중 요청을 중단하고 늦게 도착한 결과를 무시합니다.
서버는 최근 최대 12개 메시지를 검증하며, UI는 최근 11개를 전송합니다.
개발 중 브라우저 로그는 Next.js의 로컬 터미널에 출력될 수 있습니다. 실제 개인정보를 실습에 입력하지 마세요.

## 실제 수집 확인

기본 수집 목록은 BGB §551·§568 및 AufenthG §16b·§18b입니다.
Make it in Germany는 자동 수집 요청에 브라우저 확인 화면을 반환합니다. 이를 우회하지 않습니다.
해당 사이트의 수집 예시는 portal-sources.json에 분리했고, 기본 실행은 공식 법령 사이트를 사용합니다.
기본 앱의 체류 예제는 사람이 확인한 포털 안내 요약을 유지합니다.
포털 수집 실패를 관찰하려면 `python3 scripts/scrape/collect.py --manifest scripts/scrape/portal-sources.json`을 실행하세요.
