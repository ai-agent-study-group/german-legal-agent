# PO / QA 설계

[현재 구조와 기술](#doc=wiki/Home.md) · 영역별 설계: **PO/QA** · [FE](#doc=wiki/구조-FE.md) · [BE](#doc=wiki/구조-BE.md) · [LLM](#doc=wiki/구조-LLM.md) · [데이터 수집](#doc=wiki/구조-데이터-수집.md) · [DevOps](#doc=wiki/구조-DevOps.md)

제품의 목표·우선순위, 사용자 흐름·요구사항을 정리하는 역할입니다. **평가·사용자 관점도 PO 작업에 포함**하며 별도 포지션으로 나누지 않습니다.

## 1. 정할 것 (기획)

- **목표·사용자:** 누구의 어떤 Mietrecht 문제를 해결할지, 학습과 제품 중 우선순위
- **MVP 범위:** 첫 분야(Mietrecht)의 대표 질문, 꼭 필요한 기능과 보류할 것
- **사용자 흐름:** 질문 입력 → 답변·근거·출처 확인까지의 화면 흐름 ([구조 FE](#doc=wiki/구조-FE.md))
- **우선 카테고리:** [데이터 수집](#doc=wiki/구조-데이터-수집.md)의 후보 중 우선순위 선정

## 2. 평가(QA)

LLM이 들어가면 같은 입력에도 결과가 달라질 수 있어, **코드 테스트**와 **답변 품질 평가**를 나눕니다.

| 종류 | 확인하는 것 | 언제 |
| --- | --- | --- |
| 단위·흐름 테스트 | 코드 단계·흐름이 끝까지 도는지 | PR마다 CI |
| 품질 평가 | 정답과 agent 답변 비교 (근거·출처 정확도 포함) | 수동 또는 정기 |

### 평가 셋 (정할 것)

- **테스트 데이터:** Mietrecht 카테고리별 대표 질문 + 정답 근거(조항·판례). 데이터 담당과 함께 구축
- **라벨 형식:** 정답 조항·판례 ID 매칭, 출처 포함 여부, 답변 정확도 기준
- **쓰는 곳:** 모델 고르기, 프롬프트 수정 전후 비교 ([구조 LLM](#doc=wiki/구조-LLM.md))
