## 2. 데이터 수집 진행 상황 (성환님)

### 구현 내용
- 출처: **Open Legal Data API**
- 스크립트 3종: 판례 수집 / 법률 수집 / 노멀라이즈
- 원본(raw) 데이터는 별도 저장하고, 가공한 normalized 결과를 JSON으로 저장
- PO팀 기준에 따라 판례 상한 50건
- 필터 개선: 초기에는 광범위한 키워드 필터였으나, BGH·법률 조항 등을 포함한 구체적인 필터로 변경하여 주제 관련 판례/법률만 수집

### 실행 결과
| 항목 | 건수 |
|---|---|
| 판례 | 50건 |
| 법률 용어 | 98건 |
| 옵셔널 법률 | 6건 |

- 실행 시 샘플 폴더에 JSON, 요약(summary) 파일, 실패 사유 로그 생성
- 초기 실패의 주원인은 **rate limit**
  - 회원가입 후 토큰 발급 및 적용 (혜윤님이 언급했던 rate limit 이슈 대응)
  - 미인증 하루 100회 → 인증 시 시간당 5,000회로 확장 (초기 버전에는 충분)

### Q&A
- **JSON 크기** : 판례 약 1MB, 법률 약 100KB. 50건 수준에서는 JSON 파일만으로 충분
- **벡터 DB** : 도입 가능하나 현 단계에서는 로컬 JSON으로 진행, 자원이 허용되면 도입 예정
- **DB 도입 시점** : 비용이 발생하므로 2차 또는 3차에 추가 예정

### 후속 협의
- normalized 출력 스키마는 백엔드 담당 **지연님**과 협의

## 3. 파트별 공유

### 인프라·운영 (혜윤님)
- Docker Hub 게시(publisher) 작업은 이미지를 올리지 않고 Railway로 바로 배포하는 방식이라 **불필요**, 삭제 예정
- CI는 백엔드/프론트를 같은 워크플로의 job으로 분리한 구조
  - 백엔드만 돌릴 경우 백엔드 단계만, 프론트 포함 시 프론트 빌드와 린트 체크까지 수행
  - 법률 에이전트 쪽도 인프라가 유사하므로 이 구조를 참고
- Docker Compose: Railway에서 Dockerfile만으로 배포 가능하여 올릴지 여부 고민 중
- 지난주와 이번 주는 작업을 거의 하지 못함. 실제 참여는 다음 주 목요일/금요일 이후

### 프론트엔드 (호수님)
- 기획/디자인이 아직 없어 이전에 AI로 만든 임시 화면을 Vercel에 배포해 둠 (참고용, 앞으로 계속 변경)
- 현재 화면은 백엔드 없이 목(mock) 데이터로 동작
- 디자이너가 없으므로 **기획 쪽에서 레퍼런스 사이트 링크를 전달**하면 해당 UI와 비슷하게 구현 (챗봇 위치 등도 링크가 효율적)
- 기획 쪽 답변: 레퍼런스 링크를 찾아 전달하기로 함 (희정님이 샬롯님과 미팅 후 진행)

### LLM·에이전트 (승재님)
- 다음 주에 CI 작업 진행
- 다른 프로젝트에서 혜윤님이 제안한 폴더 위치 변경을 이 프로젝트 CI에도 반영 예정

- 문서와 회의록 모두 **GitHub 위키**에 바로 작성 (PR/리뷰 불필요, 저장 즉시 반영, 코드와 무관)
- 페이지를 만든 뒤 **사이드바에도 따로 추가**해야 목차에 표시됨 (양식은 위키 작성법 페이지 참고)
- 로컬에서 작성하려면 위키 git 저장소를 클론하여 작업 가능

## 5. 테스트 방법 논의
### 테스트 논의
- 제안(성환님): 정식 페이지 배포 전에 입력창/버튼만 있는 미니 GUI로 입출력을 먼저 확인. 데이터 수집 스크립트를 GUI 창으로 실행해 성공 건수와 결과를 텍스트로 보여주는 방식도 언급
- 호수님 설명: 실제 동작은 프론트가 질문을 백엔드로 POST → 백엔드가 에이전트를 돌려 답변 생성 → 프론트로 반환하는 구조. 백엔드 API가 완성되어야 하며, 에이전트 작업 최종 단계라 시간이 걸림
- 백엔드 없이 가능한 대안
  - 테스트용 엔드포인트(예: `/test`)로 간단히 확인
  - Next.js에서 로컬 JSON을 바로 화면에 표시 (제목, 내용, 작성자 등 키 값만 골라 표시)
- 단순 JSON 표시나 URL 쿼리 파라미터 기반 반환은 어렵지 않으나, 질문에 대한 답변 생성은 LLM과 백엔드 작업이 필요해 간단하지 않음. 필요하면 티켓을 만들어 진행
- 성환님이 채팅으로 구체적 의도를 채팅에 올리면 호수님이 답변

## 6. MVP 슬라이드 업데이트 필요 (기획팀)

- 백엔드 / LLM 역할 구분
  - **백엔드: 관련 자료를 검색하여 데이터를 객체로 LLM에 전달
  - **LLM: 답변 생성
  - **B1** (법률 JSON의 벡터 DB 인덱싱): 현재 방향(1차 로컬 JSON, 벡터 DB는 이후 단계)
  - 로컬 JSON을 저장해 두면 LLM이 벡터 DB 조회 시 JSON 로컬 데이터도 함께 참조해 답변을 빠르게 가져오는 구조
  - 방향: 데이터 수집은 계속 확장
