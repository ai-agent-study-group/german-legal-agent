## 현재와 앞으로 정할 구조

현재 `web/`에는 화면뿐 아니라 서버·agent 데모·자료 수집까지 함께 있습니다.
먼저 무엇을 어느 역할로 나눌지 논의하고, 구현 언어와 실행 방식에 맞춰 폴더·패키지 구조를 정할 수 있습니다.
한 저장소 안에서 폴더를 나누는 것과 여러 서버로 배포하는 것은 별개의 결정입니다.

| 기능 | 현재 데모 위치 | 분리 경로 후보 | 결정 |
| --- | --- | --- | --- |
| 사용자 화면 | `web/app/`, `web/components/`, `web/hooks/` | `web/` | ? |
| 서버 API | `web/app/api/` | `backend/` 내부 API 모듈 또는 기존 위치 | ? |
| agent 실행·모델 연결 | `web/lib/agents/`, `web/lib/providers/` | `backend/` 내부 agent 모듈 또는 기존 위치 | ? |
| 검색·본문 읽기 | `web/lib/tools/` | `backend/` 내부 검색 모듈 또는 기존 위치 | ? |
| 자료 저장소 접근 | `web/lib/sources/` | `backend/` 내부 저장소 모듈 또는 기존 위치 | ? |
| 공통 데이터 형식 | `web/lib/types.ts` 등 | 백엔드 내부 또는 공통 데이터 형식 모듈 | ? |
| 자료 수집·갱신 실행 | `web/scripts/scrape/` | `ingestion/` 내부 수집 실행 모듈 | ? |
| 출처별 수집 구현 | `web/scripts/scrape/` | `ingestion/` 내부 출처별 수집 모듈 | ? |
| 자료·검토 단계 | `web/data/` | `data/` 또는 선택한 저장소 | ? |
| 테스트 | `web/tests/`, Python 수집 테스트 | `tests/` 또는 각 모듈 내부 | ? |
| 답변 평가 | `web/docs/EVALUATION.md`의 질문 예시 | `eval/` | ? |
| 실행·배포 설정 | `web/`의 데모 설정 | `infra/` | ? |
| 공통 기획·회의 문서 | `docs/` | `docs/` | ? |

현재 자료 접근 코드는 단순 파일 복사로 옮길 수 있다고 가정하지 않습니다.
예를 들어 Next.js의 서버 코드와 파일 경로, TypeScript 타입은 서버 언어와 배포 방식을 정한 뒤 연결 방식을 확인해야 합니다.

## 기술 스택에서 정할 것

| 영역 | 현재 데모에서 사용하는 것 | 프로젝트에서 정할 질문 | 최종 선택 |
| --- | --- | --- | --- |
| 웹 | Next.js·React·TypeScript | 기존 웹을 이어갈까? 어떤 화면이 필요한가? | ? |
| API 서버 | Next.js Route Handler | 별도 백엔드를 둘까? 언어·프레임워크는? | ? |
| 자료 수집 | Python 스크립트 | 이 구현을 재사용할까? API·파일 수집과 어떻게 나눌까? | ? |
| agent | TypeScript 규칙 기반 데모 | 어떤 언어·모델·SDK를 사용할까? 프레임워크가 필요한가? | ? |
| 자료 저장 | JSON 파일 | 파일·관계형 DB·다른 저장소 중 무엇이 필요한가? | ? |
| 검색 | 키워드 검색 | 키워드·임베딩·혼합 방식 중 무엇을 실험할까? | ? |
| 환경·의존성 | 데모의 npm·Python 환경 | 언어별 환경·패키지 관리는 어떻게 할까? | ? |
| 배포·CI | 팀 운영 방식 미정 | 어떤 검사를 어디서 실행하고 어디에 배포할까? | ? |

Python 백엔드, FastAPI, uv, Pydantic, 벡터 DB 등은 선택 가능한 예시이며 채택되지 않았습니다.
그에 따른 `pyproject.toml`이나 공통 실행 명령도 아직 없습니다.

## 연결 지점에서 정할 것

| 연결 | 질문 | 합의 |
| --- | --- | --- |
| 웹 ↔ API | 요청·응답 형식, 오류, 출처·실행 기록을 어떻게 전달할까? | ? |
| API ↔ agent | 같은 프로세스의 함수 호출인가, 별도 서비스인가? | ? |
| 수집 ↔ 저장 | 자료 ID·분류·날짜·검토 상태를 어떤 형식으로 남길까? | ? |
| 검색 ↔ agent | 검색 결과와 본문을 어떤 도구·형식으로 전달할까? | ? |
| 구현 ↔ 평가 | 공통 질문과 실행 결과를 어디에 어떤 형식으로 기록할까? | ? |
